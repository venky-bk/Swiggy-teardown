# 04 — User segments and hypothesis personas

These are **hypothesis personas**, not profiles derived from Swiggy customer interviews.

## Segment A — Time-constrained weekday eater
- Goal: get a dependable lunch/dinner between work or study commitments.
- Pain hypotheses: uncertain ETA, too many choices, meal arriving after the intended break.
- Alternative: cafeteria, nearby restaurant, packed meal.
- Value lever: reliable ETA, fast reorder, clear issue resolution.

## Segment B — Budget-conscious frequent user
- Goal: order within a hard spend limit.
- Pain hypotheses: fees/discount conditions make final price hard to compare; minimum-order thresholds.
- Alternative: self-cooking, local takeaway, shared orders.
- Value lever: visible total payable price, value collections, fee clarity.

## Segment C — Dietary-goal or restriction-led user
- Goal: find food aligned with preferences (e.g., high-protein, low-calorie, vegetarian).
- Pain hypotheses: incomplete menu attributes, inconsistent restaurant descriptions, cross-contamination/allergen uncertainty.
- Alternative: trusted restaurants, manual calls, home-prepared food.
- Value lever: verified attributes and explicit uncertainty; never imply medical-grade guarantees.

## Segment D — Group/occasion organiser
- Goal: satisfy multiple tastes and budget needs for a family, team, or gathering.
- Pain hypotheses: coordination, order splitting, delivery timing, item availability.
- Alternative: direct restaurant ordering, group chat and manual coordination.
- Value lever: shareable cart, availability checks, clear ownership and checkout.

## Segment prioritisation
Start with time-constrained and budget-conscious repeat customers because the jobs are frequent and can be measured through order funnel, ETA accuracy, repeat rate, and contribution metrics. Validate with interviews and cohort data before committing.
